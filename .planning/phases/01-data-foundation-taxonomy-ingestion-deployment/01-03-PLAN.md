<objective>
Build the SEC EDGAR fundamentals extraction layer: CIK resolution with caching, a hand-rolled EDGAR HTTP client with the headers and pacing SEC requires, and — the phase's highest-risk logic — filer-type branching that extracts revenue and net income correctly for both domestic `us-gaap` filers and foreign private issuers reporting under `ifrs-full`.

Purpose: STATE.md and RESEARCH.md both flag filer-type branching as one of the two most expensive things to retrofit in this system. The shortcut (assume every company files under us-gaap) looks fine on the 45+ domestic tickers and silently produces empty fundamentals for TSM, ASML, ARM, GDS, and NBIS. This plan implements the full branch on the first pass, verified against live-recorded fixtures for one filer of each type.

Output: `cik_resolver.py`, `edgar_client.py`, and `fundamentals.py` with extraction tested against both taxonomies. Persistence and market-cap derivation land in plan 04.
</objective>

Write `backend/app/ingest/edgar_client.py` first, since the resolver depends on it.

Build a single shared `httpx.Client` via a `get_edgar_client()` accessor cached with `functools.lru_cache`. Configure it with `timeout=httpx.Timeout(10.0, connect=5.0)` and a `headers` dict whose `User-Agent` comes from `get_settings().edgar_user_agent`. This header is not optional decoration: RESEARCH.md verified empirically that a request carrying a generic library User-Agent gets a 403 from SEC, and SEC may IP-block the source for roughly ten minutes. That failure mode takes down every remaining ticker in the run rather than costing one ticker — which is exactly why it must be a shared, centrally-configured client rather than a per-call header that one code path can forget.

Note that the two EDGAR hosts differ: `company_tickers.json` is served from `https://www.sec.gov/files/`, while the XBRL APIs live on `https://data.sec.gov/`. Do not assume one base URL covers both.

Implement request pacing to stay under SEC's published 10-requests-per-second limit. A simple monotonic-clock guard enforcing a minimum interval (`EDGAR_MIN_REQUEST_INTERVAL = 0.15` seconds, deliberately conservative against the 0.1s floor) between outbound calls is sufficient at this project's single-process scale.

Wrap the request helper with tenacity: `@retry(stop=stop_after_attempt(3), wait=wait_exponential_jitter(initial=1, max=10), reraise=True)`, retrying on transport errors and 5xx/429 responses only. Do not retry on 404 — a missing CIK is a permanent per-ticker condition, and retrying it three times wastes rate-limit budget that other tickers need.

Implement `get_companyfacts(cik: str) -> dict` issuing `GET /api/xbrl/companyfacts/CIK{cik}.json` against the data host and calling `raise_for_status()`.

Now write `backend/app/ingest/cik_resolver.py`.

Implement `fetch_company_tickers_json()` retrieving `https://www.sec.gov/files/company_tickers.json` through the shared client. The response is a dict keyed by stringified index whose values look like `{"cik_str": 1045810, "ticker": "NVDA", "title": "NVIDIA CORP"}` — note `cik_str` is a plain integer despite its name.

Implement `resolve_cik(session, ticker) -> str` which checks the `ticker_ciks` table first and returns the cached value without any network call on a hit. On a miss it fetches the mapping, finds the matching ticker, zero-pads via `str(cik_str).zfill(10)`, persists a `TickerCik` row with `resolved_at`, and returns it. The zero-padding is mandatory at URL-construction time — RESEARCH.md Pitfall 1 verified that the unpadded form returns 404 while the padded form succeeds, and the symptom is confusing because the CIK itself is perfectly valid.

Raise `CikNotFoundError(ticker)` when the ticker is not in the mapping. This is a legitimate per-ticker outcome — CBRS IPO'd on 2026-05-14 and a very recent IPO may not yet be indexed in the mapping file — so the orchestrator logs it as a ticker failure per STORE-02 and moves on. It must never abort the run and must never produce a malformed URL from a `None` CIK.

Cache the fetched mapping in memory for the duration of a run so a 56-ticker cold start makes one mapping request, not 56.

Write `backend/tests/test_cik_resolver.py` covering every behavior bullet, mocking HTTP with `respx` (it mocks the httpx transport specifically, matching this hand-rolled client). Include an explicit assertion that Apple's 320193 resolves to the string "0000320193".

Write `backend/app/ingest/fundamentals.py`.

Define `CONCEPT_MAP` exactly as RESEARCH.md Pattern 2 specifies — it was derived from live-fetched companyfacts responses for both filer types, not from memory:
- Under `"us-gaap"`: revenue candidates `["RevenueFromContractWithCustomerExcludingAssessedTax", "Revenues"]`, net income candidates `["NetIncomeLoss"]`, shares candidates `["CommonStockSharesOutstanding"]`.
- Under `"ifrs-full"`: revenue candidates `["Revenue"]`, net income candidates `["ProfitLossAttributableToOwnersOfParent", "ProfitLoss"]`, shares candidates empty — foreign filers use the `dei` namespace's `EntityCommonStockSharesOutstanding` instead.

The candidate lists are ordered fallbacks, not alternatives: try each name in sequence and take the first that is present with the requested unit. This is what handles a company whose concept name changed across its own filing history.

Implement `pick_taxonomy(facts) -> str` inspecting the `facts` sub-object's keys, returning `"us-gaap"` when present, else `"ifrs-full"` when present, else raising `UnknownTaxonomyError` whose message lists the keys actually found. Every company in this ticker universe has exactly one of the two. Never index the response with a hardcoded `"us-gaap"` key — five tickers in the universe (TSM, ASML, ARM, GDS, NBIS) file Form 20-F under the IFRS taxonomy and would produce a KeyError or, worse, a silent empty extraction that looks like a healthy run with missing data.

Implement `extract_concept(facts, taxonomy, field, unit="USD") -> list[dict]` walking the candidate list and returning the first matching concept's entries for the requested unit. Filter to the requested unit explicitly — do not take the first key of the `units` dict. RESEARCH.md verified that TSM's Revenue concept reports under both `TWD` and `USD`, and taking whichever key happens to come first would silently store New Taiwan Dollar revenue as USD, producing a company that appears roughly 30x larger than it is in every downstream comparison.

Implement `extract_fundamentals(facts, years: int = 5) -> list[FactRow]`:
- Detect the taxonomy once, then extract revenue and net income entries plus the `dei` namespace's `EntityCommonStockSharesOutstanding` entries.
- Compute the history cutoff as today minus `years` years. Include filings whose `end` date is greater than or equal to the cutoff; exclude those strictly before it. The boundary is closed at the cutoff — assert this explicitly in a test rather than leaving it to whichever comparison operator got typed.
- Group entries by their `(fy, fp, accn)` tuple so revenue and net income for the same filing land on one FactRow. Entries in a companyfacts response are per-concept lists that must be joined on this key, not zipped positionally — the two concept lists are not guaranteed to be the same length or the same order.
- Carry through `accn` as `accession_number`, `filed` as `filed_date`, `end` as `period_end`, plus `fy`, `fp`, and `form`. These provenance fields are the entire point of the point-in-time design and are what plan 04's unique key is built from — a row without an accession number cannot be stored.
- Record the detected taxonomy string on each FactRow as an audit trail, so a later data-quality question about a specific figure can be answered without re-fetching.
- Leave `market_cap` unset on FactRow; deriving it requires the price series and is plan 04's job.
- Sort results ascending by `(period_end, filed_date, accession_number)` before returning. Two entries with an equal period end are fully disambiguated by the subsequent keys, so the order is total and stable across runs — which matters because an unstable order would make every run's diff look like real data churn.

Write `backend/tests/test_fundamentals.py` covering every behavior bullet using the recorded NVDA and TSM fixtures. Name the branching test `test_filer_type_branching` — 01-VALIDATION.md's per-task verification map references that exact node id.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-10 | Denial of Service | EDGAR requests missing the required identifying header | high | mitigate | A single shared `httpx.Client` configured with a settings-sourced descriptive User-Agent, so no code path can issue an unidentified request. RESEARCH.md verified a generic UA returns 403 and can trigger a ~10-minute IP block that fails every remaining ticker in the run, not just one. Enforced by an acceptance-criteria grep plus a behavioral header assertion. |
| T-01-11 | Denial of Service | exceeding SEC's 10 req/sec published limit | high | mitigate | `EDGAR_MIN_REQUEST_INTERVAL` pacing guard between outbound calls, plus an in-run in-memory cache of the ticker mapping so a cold 56-ticker start issues one mapping request rather than 56. Bounded retries prevent a failing ticker from consuming the shared budget. |
| T-01-12 | Denial of Service | unbounded EDGAR request hanging the nightly batch | high | mitigate | Explicit `httpx.Timeout(10.0, connect=5.0)` on the shared client and `stop_after_attempt(3)` on the retry wrapper; 404s are excluded from retry so permanent per-ticker conditions do not burn budget. |
| T-01-13 | Tampering | mis-detected taxonomy or currency unit silently corrupting stored figures | high | mitigate | Explicit `pick_taxonomy` branch that raises rather than defaulting, and explicit USD unit filtering rather than first-key selection. Both are gated by behavioral tests against live-recorded fixtures for one filer of each type. A wrong-currency figure is a silent integrity failure that would corrupt every downstream relative-value comparison. |
| T-01-14 | Information Disclosure | contact email in the User-Agent is transmitted to SEC | low | accept | SEC's published API policy requires a contact address; the value is supplied by the owner via env config and is never committed. Disclosure to SEC is the intended, required behavior. |

ASVS level 1; blocking threshold `high`. All four `high` threats carry `mitigate` dispositions with acceptance-criteria gates.
